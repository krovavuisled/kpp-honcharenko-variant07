# Інформаційна система керування заявками на вивезення відходів

Курсова робота з дисципліни «Кросплатформене програмування», варіант № 7. Здобувач: Гончаренко Олександр Олександрович, 204-ТН, 2026–2027 навчальний рік.

Застосунок веде довідники контейнерних майданчиків і транспортних засобів, реєструє заявки та дає змогу планувати виїзди. JavaFX-клієнт надсилає HTTP/JSON-запити до Tomcat 9. Servlet передає запити Service, а DAO виконує параметризовані SQL-запити до MySQL.

## Перший запуск на Windows

Потрібні Windows 10 або 11 x64, Windows PowerShell 5.1 та Інтернет для завантаження інструментів і залежностей Maven. Для MySQL на Windows потрібен [Microsoft Visual C++ Redistributable x64](https://learn.microsoft.com/en-us/cpp/windows/latest-supported-vc-redist/). Папка проєкту має бути доступна для запису, а повний шлях до неї має складатися з ASCII-символів через [обмеження файлових шляхів MySQL на Windows](https://dev.mysql.com/doc/refman/8.4/en/windows-restrictions.html). Наприклад, можна використати `C:\Coursework\WasteCollection` у доступному для запису місці.

1. Склонуйте репозиторій або повністю розпакуйте ZIP з кодом.
2. У корені проєкту, де розташований `Start.cmd`, відкрийте PowerShell і виконайте:

   ```powershell
   powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\Setup.ps1
   ```

3. Після успішного завершення Setup виконайте `.\Start.cmd`. Перший запуск створить локальну базу з `database.sql`, завантажить залежності Maven, збере сервер і клієнт, запустить Tomcat і відкриє JavaFX.
4. Для зупинки виконайте `.\Stop.cmd`. Під час наступних запусків локальні дані зберігаються.

Setup розпаковує JDK 21, Maven, MySQL 8.4 та Tomcat 9 у локальну `.tools`. Скрипти використовують окремий Maven-кеш у `.tools/m2`. У `.runtime/settings.json` створюється локальний пароль. Типові порти на `127.0.0.1` — MySQL **3309**, HTTP **8087**. Якщо вони зайняті, після Setup і до першого Start змініть `mysqlPort` та `httpPort` у цьому файлі. Якщо змінюєте порт після першого запуску, спочатку виконайте Stop зі старими налаштуваннями. Після зупинки узгодьте HTTP-порт також у `.runtime/tomcat/conf/server.xml`, якщо файл вже створено. Пароль залишається локальним. Журнали запуску містяться у `.runtime`.

## Ручний запуск

Використайте JDK 21, Maven, MySQL 8.4 і Tomcat 9.x. Tomcat 10 і новіші використовують інший простір імен Servlet. Виконайте `database.sql` з правами створення БД і створіть власного користувача MySQL з правами SELECT, INSERT, UPDATE, DELETE для бази `waste_collection`.

1. У середовищі процесу Tomcat задайте `DB_URL`, `DB_USER` та `DB_PASSWORD`. Приклад URL для локального серверу — `jdbc:mysql://127.0.0.1:3309/waste_collection?useSSL=false&allowPublicKeyRetrieval=true&characterEncoding=UTF-8&serverTimezone=UTC`. Використайте свої порт та облікові дані.
2. З кореня проєкту виконайте `mvn -f server/pom.xml clean package`. Розмістіть `server/target/waste-collection-server.war` у каталозі `webapps` і запустіть Tomcat.
3. Для клієнта задайте `API_BASE_URL` за адресою фактичного Tomcat, наприклад `http://127.0.0.1:8087/waste-collection-server/api`. З кореня проєкту виконайте `mvn -f client/pom.xml clean test javafx:run`.

## Модель даних і демонстрація

Редагована схема таблиць і зв’язків для diagrams.net збережена у [docs/database-schema.drawio](docs/database-schema.drawio).

| Вкладка | Дані |
| --- | --- |
| Майданчики | Код, назва, адреса та місткість у контейнерах |
| Транспорт | Номерний знак, модель, вантажопідйомність у кілограмах та доступність |
| Заявки | Майданчик, тема, вхідні фактори, обчислений пріоритет і стан |
| Виїзди | Заявка, транспорт, запланована дата та примітка |

Створіть майданчик і активний транспорт. Створіть заявку для майданчика зі заповненням 80%, санітарним ризиком 60 і простроченням 36 годин. Пріоритет дорівнює **65,50**. Спробуйте запланувати її до створення виїзду, щоб побачити предметну перевірку. Створіть виїзд з активним транспортом і послідовно переведіть заявку через **СТВОРЕНО → ЗАПЛАНОВАНО → ВИКОНУЄТЬСЯ → ВИКОНАНО**. Операції переходу доступні окремо від звичайного редагування.

Сервер обчислює `I = 0,40 × F1 + 0,35 × F2 + 0,25 × F3`. `F1` — відсоток заповнення, `F2` — оцінка санітарного ризику від 0 до 100, де 0 означає відсутність ознак ризику, 50 — помірний ризик, 100 — критичний. `F3 = min(100, 100 × години прострочення / 72)`, тому прострочення 36 годин відповідає 50 балам, а 72 години або більше — 100 балам. Сервер округлює фактори й кінцевий результат до сотих за правилом HALF_UP.

## CSV і перевірка

На вкладці майданчиків виберіть `client/sample-data/sites.csv` або `client/sample-data/sites-with-errors.csv`. Імпорт виконується у фоновій JavaFX Task, яка показує прогрес і підсумок для рядків із помилками. Повторний імпорт того самого коду майданчика дає помилку дублювання. Кодування — UTF‑8, роздільник — крапка з комою. Усі поля обов’язкові.

| Поле | Формат |
| --- | --- |
| `code` | Унікальний текстовий код до 24 символів |
| `name` | Назва до 100 символів |
| `address` | Адреса до 180 символів |
| `capacityContainers` | Ціле число від 1 до 500 |

```csv
code;name;address;capacityContainers
P-EXAMPLE;Центральний майданчик;вул. Соборності, 10;4
```

Модульні тести запускаються командами `mvn -f server/pom.xml clean test` та `mvn -f client/pom.xml clean test`. У переносимому сценарії `scripts/Build.ps1` виконує `clean verify` в обох модулях. Поки працює локальний сервер, запустіть `powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\IntegrationCheck.ps1` у корені проєкту для перевірки HTTP, MySQL і бізнес правил на тимчасових записах.

## Структура

- `server/` — Maven WAR, модель, DAO, Service, Servlet і JUnit 5.
- `client/` — Maven JavaFX, HttpClient, CSV і JUnit 5.
- `database.sql` — відтворення структури MySQL та початкових записів.
- `client/sample-data/` — тестові CSV.
- `scripts/` — встановлення інструментів, складання, запуск, зупинка та HTTP перевірка.

REST API під коренем `/waste-collection-server/api` надає ресурси `/sites`, `/vehicles`, `/requests`, `/trips`. Колекції підтримують GET і POST. Запис за ID підтримує GET, PUT і DELETE. Перехід стану — PATCH `/requests/{id}/status` з тілом `{"status":"PLANNED"}`. Помилки повертаються як JSON із полем `message`.

Перебіг чистого запуску та результати перевірок наведено у [VERIFICATION.md](VERIFICATION.md). Версію для оцінювання позначено анотованим тегом `coursework-final`.
