# Результати перевірки варіанта № 7

23 листопада 2026 року на Windows 11 x64 виконано перший запуск у окремому каталозі проєкту. Setup завантажив Temurin JDK 21.0.13.1, Maven 3.9.16, Tomcat 9.0.124 і MySQL 8.4.13 з офіційних джерел. `Start.cmd` створив окрему базу з `database.sql`, заповнив порожній Maven-кеш та відкрив JavaFX-клієнт. Інструменти, база й пароль з іншого проєкту не переносилися.

В окремий порожній екземпляр MySQL додатково імпортовано незмінений `database.sql` через форму Import у phpMyAdmin 5.2.3. phpMyAdmin підтвердив виконання 10 запитів. Перевірено наявність чотирьох таблиць, трьох зовнішніх ключів і початкових записів (3 майданчики, 3 транспортні засоби, 4 заявки, 3 виїзди).

| Модуль або перевірка | Пройшло |
| --- | ---: |
| Сервер, PriorityCalculatorTest | 7 |
| Сервер, WasteServiceTest | 14 |
| Сервер, JsonContractTest | 6 |
| Клієнт, InputTest | 4 |
| Клієнт, SiteCsvTest | 9 |
| Усього тестів JUnit 5 | **40** |
| Перевірки HTTP і MySQL | **32** |

Фінальні `mvn clean test` і `mvn clean package` для сервера та `mvn clean verify` для клієнта завершилися успішно. У JUnit 5 немає помилок, невдалих або пропущених тестів. `scripts/IntegrationCheck.ps1` перевірив CRUD чотирьох сутностей, зовнішні ключі, послідовність станів, відмову планування без доступного транспорту і виїзду, обмеження редагування активного виїзду та читання збережених значень після зміни стану.

Для заповненості 80, ризику 60 та прострочення 36 годин отримано 65,50. При 100 годинах фактор прострочення обмежено 100 балами, а пріоритет тієї самої заявки дорівнює 78,00. Обидва значення підтверджено через HTTP та MySQL.

У JavaFX відкриті чотири вкладки з початковими даними. Фоновий імпорт `client/sample-data/sites-with-errors.csv` завершив обробку чотирьох рядків. Додано два записи з кодами `CSV-M01` та `CSV-M03`. Рядок 3 відхилено через нульову місткість, рядок 5 через відсутню адресу. Наявність двох доданих записів і відсутність двох відхилених перевірено через API. Для пояснювальної записки збережено п’ять знімків інтерфейсу. Тимчасові записи перевірок видалено, у демонстраційній базі залишилися 3 майданчики, 3 транспортні засоби, 4 заявки і 3 виїзди.

Окрема перевірка JavaFX Task підтвердила запис коректного CSV через API, відхилення дубля під час повторного імпорту, обробку неправильної кількості полів, нечислової місткості, неправильного заголовка й відсутнього файла. За недоступного API завдання зупинилося з одним необробленим рядком. Журнал фіксує номера відхилених рядків, причини й підсумок імпорту. Через API звірено дані MySQL до і після кожного помилкового сценарію. Після вилучення тимчасового майданчика початковий набір записів відновлено.
